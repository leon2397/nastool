# NASTool v4.0 升级计划（优化与体验版）

> 创建时间：2026-04-20
> 版本目标：v4.0
> 核心原则：**零功能增加，专注优化、重构、体验提升**

---

## 一、升级方向

**从"能用"到"好用"，从"快"到"更快"**：
1. **性能优化**：检测速度、内存占用、并发效率
2. **代码重构**：技术债务清理、架构简化
3. **用户体验**：输出美化、交互流畅、错误友好
4. **质量提升**：测试覆盖、文档完善、稳定性

## 三、阶段划分

### 🔴 Phase A：性能优化（优先级最高）

#### A-1：检测并行化
- [ ] 单设备内检测项并行（IO-bound任务并发）
- [ ] 异步HTTP/Relay请求（aiohttp替换urllib）
- [ ] 连接池复用（SSH/HTTP连接保持）

**技术方案**：
```python
# 当前：顺序执行
for check in checks:
    result = check.run()  # 阻塞

# 目标：并行执行
async def run_checks_parallel(checks):
    tasks = [asyncio.create_task(c.run()) for c in checks]
    return await asyncio.gather(*tasks)
```

**预估提升**：单设备检测速度 +50%

#### A-2：批量检测优化
- [ ] 设备间完全并行（当前是半并行）
- [ ] 结果流式输出（检测完一个输出一个）
- [ ] 进度条实时更新（tqdm/rich）

**预估提升**：批量检测速度 +100%

#### A-3：内存优化
- [ ] 检测结果流式处理（不全部加载到内存）
- [ ] 大报告分块生成（避免OOM）
- [ ] 缓存策略优化（LRU缓存检测结果）

**预估提升**：内存占用 -50%

### 🟡 Phase B：代码重构

#### B-1：main.py 拆分
**当前**：4330行，所有CLI逻辑在一个文件
**目标**：
```
nastool_cli/
├── __init__.py
├── main.py              # 入口，仅200行
├── commands/
│   ├── __init__.py
│   ├── diagnose.py      # 诊断命令
│   ├── device.py        # 设备管理
│   ├── batch.py         # 批量检测
│   ├── compare.py       # 对比分析
│   ├── monitor.py       # 实时监控
│   └── plugin.py        # 插件管理
├── options.py           # 参数解析
└── output.py            # 输出格式化
```

#### B-2：配置系统统一
**当前**：配置分散在各模块
**目标**：
```python
# 统一配置中心
from nastool_common.config import Config

config = Config()
config.load("~/.nastool/config.yaml")  # 用户配置
config.load("./nastool.yaml")          # 项目配置
config.get("relay.url")
config.get("diagnosis.timeout", default=30)
```

#### B-3：错误处理重构
**当前**：错误信息散落，用户难以理解
**目标**：
```python
class NastoolError(Exception):
    """统一错误基类"""
    def __init__(self, code, message, suggestion):
        self.code = code  # 如 "E1001"
        self.message = message
        self.suggestion = suggestion  # 修复建议

# 用户看到：
# [E1001] 连接失败: 无法连接到 192.168.1.100:22
# 建议: 检查设备IP是否正确，或尝试 ping 192.168.1.100
```

#### D-3：稳定性提升（生产级健壮性）

**IO操作健壮性：**
- [ ] **超时控制**：所有外设/IO操作必须加超时（默认30s，可配置）
- [ ] **重试机制**：网络请求自动重试（指数退避，最多3次）
- [ ] **异常捕获**：禁止卡死/阻塞，异常可恢复
- [ ] **句柄管理**：文件、socket、串口用完必关闭（上下文管理器）

**容错与降级：**
- [ ] **优雅降级**：设备不存在、驱动异常时只报错不崩溃，自动跳过
- [ ] **数据校验**：温度/电压等数据做范围校验，脏数据不导致逻辑错乱
- [ ] **硬件适配**：硬件路径不写死，自动扫描识别，适配不同ARM平台

**资源保护：**
- [ ] **日志滚动**：自动切割（10MB×5），禁止无限写满磁盘
- [ ] **CPU保护**：循环逻辑必须加休眠（asyncio.sleep），禁止死循环占满CPU
- [ ] **内存监控**：72小时连续运行无内存泄漏

**可靠性指标：**
- [ ] **连续运行**：支持72小时稳定运行，无CPU飙高、无闪退
- [ ] **崩溃捕获**：全局信号捕获，段错误等异常记录日志不闪退（Python层）
