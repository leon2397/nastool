# 术语表

> 同一件事只有一个词。文档、代码、报告三处必须用同一套说法，否则读的人会以为是两件事。
>
> 排序：按概念簇，不按拼音。

---

## 核心对象

| 术语 | 英文 / 代码键 | 定义 | 不是什么 |
|---|---|---|---|
| **检测项** | check / `CheckResult` | 一条独立的判断，例如"数据盘容量够不够"。对应一个带 `@check` 的函数 | 不是"采集"——检测项不做 IO，只读已采到的事实 |
| **采集器** | collector / `collect_*()` | 只负责把事实取回来的函数，**不做任何判断** | 不是检测项，不产生 PASS/FAIL |
| **事实** | facts / `*Facts` | 采集器返回的数据结构。它是"读数"，不含结论 | 不是证据——证据是检测项挑选出来写进报告的那一小部分 |
| **证据** | evidence / `Evidence` | 检测项用来支撑结论的具体读数，含来源、键、值、数值、趋势 | 不是日志，不是全部事实 |
| **判定** | judgement | 检测项执行后产出的结果：一个状态 + 一句摘要 + 若干证据 | 不是"评分"——判定发生在评分之前 |
| **报告** | report / `Report` | 一次完整运行的产物，含元信息、全部检测项、评分、覆盖度 | 不等于 JSON——终端/HTML 也是报告的呈现 |

## 状态

| 状态 | 代码 | 含义 | 计分 |
|---|---|---|---|
| **通过** | `PASS` | 查到了，且正常 | 1.0 |
| **告警** | `WARN` | 查到了，有问题但还能用 | 0.5 |
| **严重** | `FAIL` | 查到了，确认是故障 | 0.0，并触发总分封顶 59 |
| **不可判定** | `UNKNOWN` | **该查但没查到**（权限、命令缺失、数据为空） | 不计分，**拉低覆盖度** |
| **不适用** | `SKIP` | **这台机器没有这个概念**（平台不支持、依赖缺失、没有对象） | 不计分，**不进分母** |

> `UNKNOWN` 与 `SKIP` 的区别是整套可信度设计的支点，见下方辨析。

---

## 评分

| 术语 | 代码键 | 定义 |
|---|---|---|
| **分类** | `category` | 检测项的归属，共 7 类：`system` / `storage` / `network` / `services` / `security` / `ai` / `usb` |
| **分类权重** | `Profile.weights[category]` | 这一大类在总分里占多少（如 nas 场景 storage 34） |
| **检测项权重** | `@check(weight=...)` | 同类内部，这一项相对别的项有多重要（1–6） |
| **分类得分** | `CategoryScore.score` | 该类内按检测项权重加权的平均，0–100；一项都没判定时为 `null` |
| **总分** | `Score.total` | 各分类得分按分类权重的加权平均，再经封顶规则修正 |
| **等级** | `Score.grade` | `A ≥90` / `B ≥80` / `C ≥60` / `D <60` |
| **封顶** | `cap` / `cap_reason` | 特定条件触发时强行压低总分，理由写进 `cap_reason`，不静默生效 |
| **盲区** | `blind_percent` | 适用项里不可判定的比例 = `unknown / applicable` |

## 覆盖与可信

| 术语 | 代码键 | 定义 | 与相近概念的区别 |
|---|---|---|---|
| **总项数** | `Coverage.total` | 本次运行的检测项总数（含 SKIP） | — |
| **适用项** | `Coverage.applicable` | `total − skipped`，即"这台机器上本该能查的项" | 覆盖度的**分母**是它，不是 `total` |
| **判定数** | `Coverage.judged` | 真正得出结论的项数（PASS+WARN+FAIL） | — |
| **不可判定数** | `Coverage.unknown` | UNKNOWN 的数量 | — |
| **覆盖度** | `Coverage.percent` | `judged / applicable × 100` | 回答"**查了多少**" |
| **置信度** | `confidence` | 0–1，这一项的结论有多可靠；整份报告取按权重加权平均 | 回答"**查到的有多可靠**" |

## 场景与筛选

| 术语 | 代码键 | 定义 |
|---|---|---|
| **场景** | `profile` | 一套预设：权重 + 启用分类 + 阈值。四种：`nas` / `verify` / `dev` / `ai` |
| **启用分类** | `Profile.active` | 这个场景下哪些分类会被执行。**没启用的分类不检测** |
| **阈值** | `thresholds` | 判定用的分界线（磁盘 80% 告警等），场景可覆盖，芯片可再覆盖 |
| **筛选** | `--only` / `--skip` | 在场景范围内再做一次增减，模式匹配检测项 id |
| **追加** | `--enable` | 临时把某个分类加进本次运行（取其保底权重 8） |

## 历史

| 术语 | 定义 |
|---|---|
| **设备指纹** | `sha256(hostname \| arch \| platform_model \| vendor)[:16]`。用来判断两次报告是不是同一台机器 |
| **运行记录** | history 里的一次运行，含完整报告 JSON |
| **逐项对比** | `diff`——按检测项 id 与证据键对比两次运行，不只是比总分 |
| **变化类型** | `new_failure` / `still_failing` / `evidence_worsened` / `new_warning` / `improved` / `evidence_improved` / `evidence_changed` / `fixed` / `added` / `removed` |
| **趋势** | `Evidence.trend`——`up_bad`（涨是坏事）/ `up_good`（涨是好事）/ `""`（中性，不参与好坏判断） |

## 版本

| 术语 | 字段 | 含义 |
|---|---|---|
| **产品版本** | `version` | `0.3.1`，工具自身版本，随功能变化 |
| **报告版本** | `report_version` | `3.0`，**JSON 结构契约版本**。字段增删改必须升它 |
| **历史库版本** | `runs.version` | 记录当时的产品版本，便于回溯"这个结论是哪版工具给的" |

三者互不相等，也不要求同步。看到 `version: 0.3.1` 与 `report_version: 3.0` 并存是正常的。

## 五个最容易混淆的

### 1. `UNKNOWN` vs `SKIP`

|  | `SKIP` | `UNKNOWN` |
|---|---|---|
| 意思 | 这台机器**没有**这个概念 | 这台机器**有**，但我没查到 |
| 例子 | Windows 上查 `/proc/mdstat` | Linux 上 `smartctl` 权限不足 |
| 进分母吗 | 不进 | 进 |
| 影响分数吗 | 不影响 | 不直接扣分，但拉低覆盖度 → 可能触发盲区封顶 |
| 是问题吗 | 不是 | **可能是**——这正是需要让人看见的部分 |

**判据一句话**：如果换一台同型号的机器、给足够权限就能查出来，那它是 `UNKNOWN`；
如果换任何一台这样的机器都查不出来，那才是 `SKIP`。

### 2. 覆盖度 vs 置信度

覆盖度是"我查了几成"，置信度是"查到的这些有多可靠"。一份报告可以覆盖度 100% 但置信度 0.6
（全部靠回退路径推断出来的），也可以置信度 0.95 但覆盖度 40%（只查了最容易的几项，但都很准）。
**两者都要看，缺一不可。**

### 3. 分类权重 vs 检测项权重

分类权重决定"存储 vs 网络"谁更重要（几十的量级）；检测项权重决定"坏扇区 vs 通电时长"
谁更重要（1–6）。两者在报告里显示的位置不同：分类权重在分项条形图旁，检测项权重不显示。

### 4. 总分 vs 等级

等级不是总分的函数——两条封顶规则会**先压低总分再算等级**。所以不存在"C 级但 85 分"，
只会出现"85 分被压到 74 分，于是 C 级"。看到等级与直觉不符时，先看 `cap_reason`。

### 5. "没查" vs "没问题"

报告里最容易误导人的一句话是"全部通过"。全 SKIP 的过滤结果也满足"没有失败"，
但什么都没查。这种情况的正确措辞是**"没有可判定的项"**，不是"通过"。
（这个坑踩过一次，见 [memo/gotchas.md](memo/gotchas.md) GOTCHA-007。）
