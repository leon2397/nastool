# 架构决策记录（ADR）

> 记录**为什么**这样设计，而不是怎样设计。怎样设计看 [ARCHITECTURE.md](../ARCHITECTURE.md)。
>
> 一条 ADR 一旦写下就不再修改。若结论被推翻，**新写一条**并标注取代关系，而不是改写历史——因为「当时为什么这么想」本身是资产。

## 什么值得记一条 ADR

满足以下任一条件：

- 决策会影响**外部**（报告格式、CLI 参数、退出码）
- 决策**放弃了**一个看起来更简单的方案
- 未来有人会问「为什么不改成那样」
- 决策的代价是**已知且必须承受**的（例如零依赖限制了功能）

## 模板

```markdown
# NNNN. 一句话决策

- 状态：提议 / 生效 / 已废弃（被 NNNN 取代）
- 日期：YYYY-MM-DD
- 影响：契约 / 评分 / 报告 / 部署 / 开发流程

## 背景
当时面对什么问题，有哪些约束。

## 决策
做了什么。

## 后果
### 好处
### 代价（必须诚实写出）
### 缓解

## 考虑过但否决的方案
为什么不选那些看起来更简单的做法。
```
