# nastool v7.1.0 升级计划

> 制定日期：2026-04-16
> 主题：测试流程 × 诊断体验优化
> 当前版本：v7.0.0-beta（arm_diagnose.py 实际显示 5.0.4，存在版本号矛盾）
> 目标版本：v7.1.0

---

## 一、背景与目标

### 1.1 Jetson 真机测试暴露的问题

2026-04-16 在 Jetson Xavier NX (192.168.1.123) 上进行真机测试，18 分钟发现 **7 个 BUG**：

| ID | 优先级 | 分类 | 问题 |
|----|--------|------|------|
| BUG-001 | P1 | T-A | --quick 显示 Passed: 0/0（代码缺陷） |
| BUG-002 | P2 | T-B | 部署版本落后（86 vs 93 checks） |
| BUG-003 | P2 | T-B | gpu_detected 无法导入 check 函数 |
| BUG-004 | P1 | T-C | Jetson 缺少 jetpack_version 等专用检查 |
| BUG-005 | P1 | T-C | GPU 检测返回 "No AI accelerator" |
| BUG-006 | P2 | T-D | 测试脚本类名硬编码导致误报 |
| BUG-007 | P1 | T-A | HTML 报告未生成 |

**根本问题：**
1. 版本号矛盾：`arm_diagnose.py __version__ = "5.0.4"` ≠ CHANGELOG.md v7.0
2. 测试前未验证被测版本，导致 T-B 类问题混入测试结果
3. 测试脚本与模块名耦合，Jetson 环境差异（cpu_usage vs cpu_temp）导致 T-D 类误报
4. 核心功能缺陷（BUG-001, BUG-007）未在本地发现就上了真机

### 1.2 v7.1.0 目标

```
"让测试可重复、可信、可解释"
- 可重复：任何时间/地点跑测试，结果一致
- 可信：测的是真实问题，不是版本差异或脚本误报
- 可解释：每个 BUG 有清晰的分类和来源
```

### F2：内置首次运行设备就绪检查

**现状：** 无检查，直接跑诊断

**改进方案：** 首次运行自动提示，融入 `--quick`/`--full` 流程

```
首次运行检测流程：
1. 读取 ~/.nastool/version_cache.json
2. 对比当前版本 vs 上次运行版本
3. 如果版本变化 → 显示版本变化摘要（3行）
4. 如果版本变化 → 检查 registry count 有无变化
5. 执行诊断（不阻断）
```

**版本变化提示示例：**
```
🔔 nastool v7.1.0 更新
   • 新增 7 个检查项（System +2, AI +5）
   • 修复已知问题 3 个
   • 改进 Jetson GPU 检测逻辑
   • [跳过] [查看更新日志]
```

**实现细节：**
- 缓存文件：`~/.nastool/version_cache.json`
  ```json
  {
    "version": "7.0.0-beta",
    "git_hash": "a3f8c12",
    "checks_count": 93,
    "last_run": "2026-04-16T11:22:00",
    "device_profile": "jetson-xavier-nx"
  }
  ```
- 离线/内网场景：版本检查超时 5s 后自动跳过，不阻断流程
- 用户选择"跳过"：写入 `skip_version_notice: true`，同一版本不再提示

**改动范围：**

- `nastool/arm_diagnose.py`：启动流程集成

### F3：通用测试运行器

**现状：** 测试脚本硬编码模块名（如 `cpu_usage`），Jetson 上实际是 `cpu_temp`，导致 T-D 类误报

**改进方案：** 读取 registry 动态探测，不依赖具体模块名

```python
# nastool/test/test_runner.py（新增）
"""
通用测试运行器 - 读取 registry，动态探测，不依赖模块名
"""
from checks.registry import _CHECKS
from typing import Optional

class TestRunner:
    """动态测试运行器"""

    def run_check(self, check_id: str, timeout: int = 30) -> TestResult:
        """通过 registry 运行单个检查，不关心模块路径"""
        if check_id not in _CHECKS:
            return TestResult(error=f"Check '{check_id}' not found in registry")

        check_fn = _CHECKS[check_id]
        try:
            # 统一调用接口：检查注册时已统一接口
            result = check_fn()
            return TestResult(
                check_id=check_id,
                passed=result.passed,
                message=result.message,
                severity=result.severity,
            )
        except Exception as e:
            return TestResult(check_id=check_id, error=str(e))

    def run_all(self, categories: Optional[list] = None) -> TestSummary:
        """运行所有检查或指定分类"""
        ...

    def generate_report(self, format: str = "md") -> str:
        """生成测试报告"""
        ...

# 命令行接口
# python -m nastool.test.test_runner --all
# python -m nastool.test.test_runner --category AI
# python -m nastool.test.test_runner --check gpu_detected
```

**改动范围：**
- `nastool/test/test_runner.py`（新增）：核心运行器
- `nastool/test/conftest.py`：pytest fixtures（已有，补充）
- `nastool/test/test_functional.py`：重写为基于 runner
- `test_jetson.py` → `test/devices/test_jetson.py`（迁移 + 重写）

**优先级：** P1
**工时：** 4-6h
**依赖：** F1（F1 提供的版本信息用于测试报告 header）

### F4：BUG 分类标准化

**现状：** 所有 BUG 混在一起，"代码缺陷"和"版本差异"不区分

**改进方案：** 统一 BUG 分类体系，写入 `TEST_BUGS_*.md` 模板

```
BUG 分类体系：
├── T-A：代码缺陷（本地代码本身有 bug）
│   ├── 特征：本地测试也能复现
│   └── 修复策略：定位代码，单元测试覆盖
├── T-B：版本差异（被测版本落后，功能不完整）
│   ├── 特征：同步最新代码后消失
│   └── 修复策略：部署流程优化
├── T-C：环境适配（目标平台特殊限制）
│   ├── 特征：特定设备/环境上出现，其他环境正常
│   └── 修复策略：设备 profile + expected_results.json
└── T-D：测试设计（测试方法/脚本问题，不反映真实质量）
    ├── 特征：测试脚本问题，代码本身正常
    └── 修复策略：改进测试脚本

判断逻辑：
1. 本地能复现 → T-A
2. 本地不能复现，但其他设备能 → T-C
3. 同步最新代码后消失 → T-B
4. 测试脚本换了就正常 → T-D
```

**Jetson 测试 BUG 重新分类：**
| ID | 原分类 | 新分类 | 理由 |
|----|--------|--------|------|
| BUG-001 | P1 | T-A | 本地也能复现，代码缺陷 |
| BUG-002 | P2 | T-B | 版本落后，同步后消失 |
| BUG-003 | P2 | T-B | 同上，依赖 BUG-002 |
| BUG-004 | P1 | T-C | Jetson 环境差异 |
| BUG-005 | P1 | T-C | Jetson 无 nvidia-smi |
| BUG-006 | P2 | T-D | 测试脚本类名错误 |
| BUG-007 | P1 | T-A | 本地测试也能复现 |

**改动范围：**
- `TEST_BUGS_*.md` 模板更新：增加 `Type:` 字段
- `docs/TESTING.md`（新增）：测试规范文档
- `nastool/test/TEST_GUIDE.md`（新增）：开发者测试指南

**优先级：** P2
**工时：** 1h
**依赖：** 无

# test/devices/test_jetson.py
def test_jetson_checks():
    expected = load_expected_results("jetson-xavier-nx")
    runner = TestRunner()

    for check_spec in expected.checks:
        result = runner.run_check(check_spec.check_id)

        # 1. 检查是否存在
        if result.error and "not found" in result.error:
            assert False, f"Missing check: {check_spec.check_id}"

        # 2. 检查 forbidden errors
        for forbidden in expected.forbidden_errors:
            assert forbidden not in result.error

        # 3. 检查预期状态
        assert result.passed == check_spec.expected_passed, \
            f"{check_spec.check_id}: passed={result.passed}, expected={check_spec.expected_passed}, msg={result.message}"

## 七、风险与备选

| 风险 | 影响 | 备选方案 |
|------|------|---------|
| F6 版本检查 API 不稳定 | P3 功能降级 | 关闭版本检查，用户手动配置 |
| F5 多设备 JSON 维护成本高 | P2 | 提供 `--generate-expected` 自动生成模板 |
| Jetson 网络不稳定（内网） | F2/F6 版本检查超时 | 超时 5s 自动跳过 |
| @check() 装饰器接口变更 | F3 通用运行器需适配 | 保持向后兼容，当前已是统一接口 |
